# Weak-ink neural candidate experiment

This is a small CPU-only research model for faint whiteboard marks. It is an
optional candidate layer and never writes confirmed board state by itself.

Run from the repository root:

```sh
.venv/bin/python experiments/weak-ink/train.py
```

The script generates synthetic boards with dark, faint red, low-contrast grey,
gradients, blur, sensor noise and a dirt-like negative line. It trains a tiny
two-layer NumPy MLP on local grayscale, colour, edge and directional features.
The test scenes use independent seeds. No private capture, user image, or live
database is read. The canonical V1 artifact is `models/weak_ink_v1.npz` and is
reproducibly regenerated by the script; the similarly named historical file
under this directory is not loaded by runtime code.

The output probability map is the `WeakInkModel.predict_proba(bgr, known=None)`
method. With a `known` mask, pixels outside the confirmed/observed region are
forced to zero. `candidate_mask(model, bgr, threshold=0.72)` preserves 1-pixel
marks and intentionally performs no morphological opening. Production code
must keep this separate from confirmed pixels and must reject low-confidence,
saturated glare, and occluded regions. The model score is not a calibrated
probability. The learned model is a research candidate, not yet a replacement
for the stronger traditional contrast baseline in every synthetic scene.

## V2 and V3 studies

`train_v2.py` trains `models/weak_ink_v2.npz` with 13 multi-scale context
features. Its synthetic holdout checks colour and bright-band failure modes,
but its overall precision does not beat the local-contrast baseline. It is not
enabled in the live estimator.

`train_patch_v3.py` is a separate hard-candidate experiment. It first creates
the traditional local-contrast candidate, then trains a tiny 9x9 patch MLP to
reject stains, board rims and JPEG-like texture. Training uses straight and
polyline families only. Ellipse and self-crossing families are held out by
seed family. The latest full-frame run produced precision 0.952 and recall
0.874 (47,593 TP, 2,395 FP, 6,887 FN over 54,480 truth pixels and 774,960
negative pixels). The unfiltered traditional detail>=4 baseline has precision
0.456 and recall 0.954 on the complete frame. At the closest tested traditional
false-positive budget (detail threshold 21, 2,991 FP), its precision/recall are
0.903/0.537. Thus V3 improves recall at a lower false-positive rate in this
synthetic study, but is not evidence of real-board accuracy or calibrated
probabilities. The V3 weights remain under this experiment folder until a
blind real-board review shows that weak-line recall improves without adding
false strokes.

`predict_full_frame(image, weights, threshold=.5, known=None)` is the
standalone research entry point: it accepts a BGR uint8 frame and returns a
full-frame float32 score map plus binary mask; pixels outside traditional
candidates (or `known`) are zero. The synthetic full-frame result above is
the only public benchmark; any real-capture review remains local and is not
part of the release.

The only packaged research weights are `models/weak_ink_v1.npz` (historical
baseline) and `models/weak_ink_v2.npz` (context study). Neither is enabled by
the live estimator. `experiments/weak-ink/weak_ink_patch_v3.npz` is a
research-only output; rerunning a study never replaces a packaged weight.

Reproduction (from `physical-whiteboard/`, with the project `.venv`):

```sh
.venv/bin/python experiments/weak-ink/train.py
.venv/bin/python experiments/weak-ink/train_v2.py
.venv/bin/python experiments/weak-ink/train_patch_v3.py
```

These commands write fresh outputs below `experiments/weak-ink/artifacts/`
by default, including V3's result and weight. Replacing a checked-in V3
sample requires `train_patch_v3.py --write-output`; replacing a packaged V1/V2
file requires the explicit `--write-model` flag. Dependencies are Python 3, NumPy and OpenCV; no PyTorch
or network access is required. Current packaged SHA-256 values:
